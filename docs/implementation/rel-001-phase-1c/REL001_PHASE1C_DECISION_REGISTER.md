# REL-001 Phase 1C Bounded Decision Register

These entries are phase-local authority records, not amendments to frozen architecture.

| ID               | Decision                                                                                                                        | Status                | Rationale                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------- | --------------------- | ------------------------------------------------------------------------- |
| REL001-1C-DR-001 | Reuse `IdentityContext` as post-resolution projection, not as Session storage.                                                  | ACCEPTED              | Preserves identity/authorization separation.                              |
| REL001-1C-DR-002 | Treat `x-session-id` only as an opaque lookup carrier.                                                                          | ACCEPTED              | Prevents caller-controlled authority claims.                              |
| REL001-1C-DR-003 | Perform live authorization after resolution.                                                                                    | ACCEPTED              | Preserves current permission and deny precedence.                         |
| REL001-1C-DR-004 | Do not introduce a new IdP, protocol, token format, role, capability, login operation, or external store.                       | ACCEPTED              | Keeps the boundary bounded.                                               |
| REL001-1C-DR-005 | Assign one bounded durable Session repository/UoW to Identity / Authorization.                                                  | APPROVED              | Reuses MAOS persistence ownership.                                        |
| REL001-1C-DR-006 | Make Session identity/binding provenance immutable and mutations monotonic through `sessionVersion`.                            | APPROVED              | Prevents silent overwrite.                                                |
| REL001-1C-DR-007 | Make revocation durable, append-preserving, irreversible, atomic, and restart-safe.                                             | APPROVED              | Revoked Sessions always fail closed.                                      |
| REL001-1C-DR-008 | Derive tenant and multidimensional scope from live trusted assignments.                                                         | APPROVED              | Carrier and stale Session data cannot grant authority.                    |
| REL001-1C-DR-009 | Store bounded audit references only; Audit retains semantic ownership.                                                          | APPROVED              | Avoids raw audit data, expanded PII, and secrets.                         |
| REL001-1C-DR-010 | Require server-managed `lastAccessedAt` mutation after successful Session resolution because an idle-timeout rule is canonical. | SUPERSEDED / RESOLVED | Human policy now requires authoritative access freshness.                 |
| REL001-1C-DR-011 | Use a 30-minute idle timeout, 12-hour maximum absolute lifetime, and 15-minute applicable MFA freshness window.                 | APPROVED              | Explicit human policy closes numeric freshness bounds.                    |
| REL001-1C-DR-012 | Keep production-style Staging ingress and production implementation separately unauthorized.                                    | APPROVED              | Design closure is not implementation or production authority.             |
| REL001-1C-DR-013 | Select the same-origin Control Room BFF/proxy for production-style Staging browser Session ingress.                             | APPROVED C2           | MAOS-CR-003 adopts the design; implementation remains separately blocked. |
| REL001-1C-DR-014 | Assign browser transport controls to the BFF and credential verification plus durable Session authority to Core Identity.       | APPROVED C2           | Keeps the BFF from becoming an identity or authority source.              |
| REL001-1C-DR-015 | Require explicit Session issuance/revocation and Identity provisioning permissions.                                             | APPROVED C2           | Existing Operations control authority must not be reused silently.        |
| REL001-1C-DR-016 | Require an exact approved HTTPS origin and Session-bound CSRF proof for every unsafe browser request.                           | APPROVED C2           | Preserves default-deny browser mutation semantics.                        |
| REL001-1C-DR-017 | Use a `__Host-` HttpOnly Session cookie only when every prefix and origin constraint is satisfied.                              | APPROVED C2           | Prevents silent fallback to a weaker browser transport.                   |
| REL001-1C-DR-018 | Submit the approved ingress design for C2 governance as MAOS-CR-003 without implementation or production authority.             | APPROVED C2           | Architecture adoption is approved; implementation and deployment are not. |
